# Что осталось перенести из монолита

Состояние на 2026-10-01. Монолит: `../RentAlert`, пакет `com.bsu.renalert`.

Отсортировано по сложности: сверху то, где большая часть кода уже есть в сервисах.

## 1. Админ-API (admin-ms)

Перенесено всё.

| Что | Состояние |
|---|---|
| `AdminRoommateModerationController` | перенесён: проксирует во внутренние эндпоинты roommate-ms |
| Кнопка «синхронизация кэша» (`/job-settings/cacheSync`) | не перенесена намеренно: в монолите она переносила счётчик попыток парсеров из Redis в `schedule_tasks`, а в processing-ms этого счётчика нет |
| Поиск получателей рассылки по имени (`search`) | только по id пользователя: имена хранятся в identity-ms |

## 2. Пользовательские функции

Перенесены: подтверждение email, настройки приложения (`/api/v1/identity/app-settings`), уведомление администратору о новом пользователе, настройки уведомлений по умолчанию при регистрации.

## 3. События статистики (`@UserAudit`)

Перенесены все: `LOGIN_SUCCESS` (identity-ms, вход через Telegram и админский), `FILTER_CREATED` / `FILTER_UPDATED` / `FILTER_DELETED` (identity-ms, с id фильтра), `NOTIFICATION_SETTINGS_UPDATED` (notification-ms). Публикуются через outbox в той же транзакции, что и изменение.

## 4. Telegram-бот (входящие команды)

Перенесены команды `/start`, `/help`, `/app` и кнопки под объявлением: в избранное, убрать из избранного, скрыть. Бот по-прежнему выключен по умолчанию (`TELEGRAM_BOT_ENABLED`): он работает через long polling, поэтому запускать его можно только в одном экземпляре notification-ms. Для `/app` нужен `FRONT_ADDRESS`.

## 5. Домен roommate (поиск соседей)

Переносится в `roommate-ms` по этапам. Готовы этап 0 (каркас, схема БД), этап 1 (анкеты, объявления о подселении, модерация текста, админская модерация через admin-ms, уведомления `ROOMMATE_PROFILE_APPROVED/REJECTED` через outbox) и этап 2 (лента кандидатов и объявлений с курсором, скоринг, скрытие; имена и фото из identity-ms).

В монолите остаются: лайки и пары с машиной состояний, общие избранное и фильтры, просмотры, жалобы, задачи `RoommateCandidateDigestJob` и `RoommateMatchExpiryJob`.

План переноса: [roommate-migration-plan.md](roommate-migration-plan.md).

## 6. Инфраструктура

| Что | Состояние |
|---|---|
| WebSocket-уведомления | доставляются из realtime-ms: notification-ms публикует `RealtimePushEvent` в Kafka (`notification.realtime-push.v1`), каждый экземпляр realtime-ms доставляет событие своим подключённым пользователям; масштабируется горизонтально. Отправка включается `WS_ENABLED`; канал WEBSOCKET используют типы roommate (п. 5) |
| Уведомление «приложение запущено» (`AppInitService`) | перенесено: каждый сервис шлёт `ServiceStartedEvent`, notification-ms уведомляет администратора, когда стартовали все из `app.startup.services` (окно 15 мин) |
| Синхронизация курсов при старте | не переносим: processing-ms синхронизирует через 5 минут после старта и далее каждые 6 часов |
| Периодическая синхронизация кэшей (`CacheSyncScheduler`, каждые 5 мин) | не перенесено; решить, нужно ли при кэшах с TTL |

## Известные проблемы, найденные при переносе

- **Feign использует `HttpURLConnection`**, который не умеет PATCH, поэтому внутренние эндпоинты делаются через PUT.
